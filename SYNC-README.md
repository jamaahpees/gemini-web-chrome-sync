# Cookie-Editor Gemini Sync

Fork of [Cookie-Editor](https://github.com/Moustachauve/cookie-editor), GPL-3.0-only. Existing cookie editor remains available. New Chrome sync functionality sends only explicitly allowed Google/Gemini session cookies to a paired private Tailscale HTTPS endpoint.

## Trust model

One normal Chrome profile pairs with one server target. The browser is the source of truth. The receiver checks the candidate session before replacing the backend cookie snapshot. No cookie payloads belong in logs, Git, MCP responses, or support messages. A paired installation holds a scoped bearer token in Chrome local storage; this is not an OS secret vault. Anyone controlling that browser profile can access the token and Google session.

The upstream Cookie-Editor still supports optional access to all sites for manual editing. Automatic Gemini sync is restricted separately to its Google cookie allowlist. The fork does not grant automatic sync access to other sites.

Do not expose the receiver using Tailscale Funnel. Use a dedicated private Tailscale Serve HTTPS port (8443), distinct from the existing public dashboard on 443. Tailscale membership is not enough: per-installation API authentication is mandatory too.

## Install Chrome extension

1. Run `powershell -ExecutionPolicy Bypass -File deploy/package-chrome.ps1` from the repository after verification.
2. Extract `dist/cookie-editor-gemini-sync-chrome.zip` to a persistent folder.
3. Open `chrome://extensions`, enable Developer mode, choose **Load unpacked**, and select the extracted directory containing `manifest.json`.
4. Open the extension's Gemini sync settings, enter the private HTTPS server address and one-time pairing code generated by the server administrator.
5. Grant the requested Google and server host permissions. Use a dedicated normal Chrome profile with one Google account; incognito sync is not supported.
6. Log in to Gemini normally. Cookie changes are sent automatically while Chrome is running. Verify the server acknowledgement, not just the extension's last attempted send time.

Each Chrome profile installs the same extension package but pairs separately. Do not copy another profile's extension storage or token.

## Server and account isolation

See `server/README.md` for the receiver's CLI, config and tests. Run it as an unprivileged service behind private Tailscale Serve. Secrets/config belong outside this repository and must be mode 0600.

The existing Gemini backend uses a cookie pool. Do not add several profile snapshots to that shared pool and call this isolation. Provision a dedicated backend and 9router provider for each additional profile:

```sh
python3 deploy/provision.py --name profile-b --port 8090 --dry-run
python3 deploy/provision.py --name profile-b --port 8090
```

The provisioning command runs on the server as root; it creates a container using the already installed image, dedicated data volume, private loopback admin port, private credentials, and `gweb-profile-b/*` models in 9router. It never overwrites an existing target. A failed provisioning run can leave a stopped/partial target for operator inspection; do not delete data volumes during recovery. Import the generated target config into the receiver configuration, restart the receiver, and generate a pairing code for that target.

## Operational limits

- Cookie sync does not bypass Google login, MFA, account permissions or service limits.
- A valid session does not prove that Argon can answer. Model tests must inspect actual text, including Google's HTTP-200 error messages.
- Refresh is opt-in and can interrupt a generation even in a background tab. Do not use refresh while a response is being generated.
- Chrome closed, PC asleep, missing host permission, or Tailscale disconnected means no live sync. Retry reads the newest browser snapshot rather than replaying saved cookie payloads.
- Each target must have one paired device. An account identity change requires explicit re-pairing instead of silently replacing a different account.
- The included v4.23.0 patch adds `GEMINI_BROWSER_COOKIE_SOURCE=1`: timer/fallback rotations and response cookie merging are disabled, and disabled candidate import is atomic. The deployed `gemini-web-browser-source:4.23.0` image uses this mode. The patch is in `deploy/browser-source.patch`; default upstream behavior is unchanged without the environment flag.
- Request limits apply to the shared VPS egress IP even with multiple isolated backends.

## Verification

```sh
npm ci --ignore-scripts
npm test
node --test test/provision-sync.test.cjs
python -m unittest discover -s server -p 'test*.py'
```

The upstream development dependency tree has audit findings; `npm audit --omit=dev` currently reports no production dependency findings. The browser package contains no Node dependencies. Test output from existing upstream devtools tests may contain their pre-existing diagnostic messages.
